# Private group workspace recovery

Migration 033 adds a private reconstruction boundary for explicitly isolated
Git/Terraform fixtures. It does not enable public fleet execution, customer
Terraform pipelines or a financial claim. Migrations 001–032 and their existing
signatures remain unchanged.

A current PostgreSQL head proves database ownership. It cannot prove that an
old worker has stopped executing. Reconstruction therefore requires both an
independently commissioned runtime controller and a positive native terminal
record made before the old workspace disappeared.

## Immutable authority

An operator installs a distinct controller public key and the initial exact
runtime identity at a zero-record journal head. The signer, ledger and pipeline
keys cannot substitute for that controller key. The controller identity has no
native apply or financial-write permission.

Before publishing `APPLIED`, a managed reconstruction chain must select its
pipeline-signed positive terminal. The terminal binds tenant, chain, program,
authorization, command, operation, fence, issued head, workspace generation,
before/after state and exact versioned capture/review/state references. Signed
terminal IDs and archive object IDs are separate identities. A matching model,
an expired claim or a missing terminal cannot supply success evidence.

The private repository resolves these records under the actual graph, workload,
current-head and issued outbox fences. Prepared proof bytes are compared with
immutable PostgreSQL pins again after taking the fence. The native producer
authenticates exact encrypted object versions and revalidates the complete
Git/state/artifact proof. Neither a public request nor an analytical worker can
supply an authoritative snapshot.

The replacement controller must attest that it observed removal of the exact
owned old container. Its signature binds the old and new container IDs, image,
generations, tenant, program and chain. The replacement gets an empty workspace;
the native worker receives neither the controller private key nor a Docker
socket. A caller boolean or lease timeout is insufficient.

## Reconstruction and remaining duty

Materialization reconstructs exact Git objects, ancestry and authenticated state
without invoking Terraform. It preserves the existing positive outcome and
dispatch marker, so reconstruction cannot repeat an apply. Uncertain or missing
terminal evidence remains `UNKNOWN`. Subsequent recovery requires a fresh exact
saved plan and the normal durable command/receipt protocol.

Original owned restoration survives source revocation, pause and approval
expiry. Legacy unregistered journals keep their original semantics. A second
loss cannot reuse the first generation's terminal as proof of the newer worker;
unsupported reconstruction remains blocked. Recovery-continuation segments are
not silently converted into original journals.

This increment does not claim a deployed durable recovery controller, external
alert delivery, repeated-loss operational acceptance or complete recovered
application health. The separate full health-window lab and a reconstruction
component result must not be combined into a customer operating-loop claim.
