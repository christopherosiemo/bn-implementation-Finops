# Native telemetry and capacity evidence

Native telemetry is an additive path alongside the guarded current-minute activity and SLO ingress. It cannot backfill those contracts. Registered Prometheus range-vector reads preserve actual scrape timestamps; authenticated OTLP/HTTP accepts protobuf with explicit temporality and resource binding. A historical query is evidence of the samples returned, never evidence that the platform previously received a heartbeat or observed an application SLO.

The API owns connection and metric-definition revisions, workload requirements, revocation and sealed evaluation records. The reader and ingress run with separate PostgreSQL identities. Only the reader receives approved endpoint bindings and its private evaluation token; machine ingress uses a dedicated OIDC audience and exact registered subject. Human console tokens cannot submit native batches. None of these identities can sign plans, execute customer mutations or write financial claims.

Publication records a durable batch attempt, stores exact protocol bytes in versioned tenant-scoped objects, stores canonical samples in another pinned object, writes provenance-aware ClickHouse samples and a batch manifest, then publishes an immutable receipt. Partial writes retain checkpoints and cannot produce a receipt. An empty export still needs both storage acknowledgements. Retries preserve the original receipt clock; changed bytes under an existing idempotency key conflict. Object reads pin versions and verify hashes. Revocation and inventory reassignment preserve history while preventing new authority.

Prometheus `increase()` and held values from `query_range` are not exact observations in this contract. The reader uses native range vectors and recorded counter epochs. OpenMetrics counter-family names are resolved according to the `_total` convention. Units are preserved exactly, including OTel UCUM `s`; conversion requires an explicit calculation outside the receipt. Resets, gaps, unsupported statistics, partial OTLP rejection and uncertain histogram bounds remain visible. Native histograms and exponential OTLP histograms are currently explicit unsupported inputs rather than silently accepted distributions.

History uses complete local calendar days: fourteen for explicitly non-production inventory and profile, thirty for production or unknown classification, ninety for declared seasonality. The evaluation keeps a small segment-reference preview with the full population count and digest. Archived canonical batches remain the source of the population. Same semantic observations from repeated transport merge their provenance; different values for the same source/stream/point block evaluation. Query completion does not establish sample coverage. Current evaluators stop explicitly above 250,000 unique samples or 2,048 selected receipts; larger/high-resolution histories require the streaming evaluation increment and cannot obtain an incomplete positive result.

Workload safety profiles declare replica/zone minima, maintenance windows, recurring and absolute blackouts, demand events, saturation limits, recovery requirements and simultaneous-change limits. A declaration does not prove recovery. Unknown RPO stays null. Full-day windows use `00:00` to `24:00`; `24:00` is permitted only as an end. Both repeated DST hours obey their local calendar rule. CPU/memory spare fractions and additive reserve above forecast are different quantities with explicit integer parts-per-million units.

The private Python capacity model computes distributions, peaks, weekday/hour forecasts, rolling-origin backtests and block prediction intervals. Unsupported horizons and uncalibrated future breach probabilities remain unavailable. Low CPU with 95% memory, unobserved memory, inadequate history, seasonal demand and incompatible hardware block relevant candidates. The [read-only EC2 hardware path](native-hardware-capacity.md) now connects immutable native receipts and observed historical capacity denominators to that worker. It supports a constrained Linux/Nitro, single-gp3 population and persists a distinct native result history. Native contracted candidate pricing and complete commitment exposure remain required: unknown costs stay null, and all results remain blocked from execution. The earlier blocked assessment records and proposal contract remain preserved independently.

Local acceptance uses a real instrumented HTTP gateway, Prometheus, the official OTel collector, Keycloak, PostgreSQL roles, versioned MinIO objects and ClickHouse. The gateway emits only requests actually served, latency observations and actual process creation epochs. It does not manufacture CPU/memory or genuine fourteen-day history. Provider-shaped historical data in deterministic tests remains labelled as a double. The connected console exposes source revisions, durable sync status, coverage gaps and blocked results through scoped paginated APIs.

Run the normal Compose bootstrap/build/migration, then `node scripts/native-smoke.mjs` and `node scripts/native-otel-smoke.mjs`. The latter mounts a local ignored OAuth client secret file into a temporary collector and revokes its fixture connection afterward. These scripts accept no remote target and provision no cloud resource. Hosted configuration is documented in [native deployment controls](../deploy/NATIVE_TELEMETRY.md); it is disabled by default.
