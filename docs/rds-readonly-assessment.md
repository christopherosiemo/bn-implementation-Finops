## Implemented boundaries

- Native AWS reads validate STS identity, tenant, account, ARN and region. Bounded pagination and throttling handling cover instances, clusters, replicas, tags, parameters, reservations, orderable options, modification constraints and catalogue capacity. Optional Database Savings Plans and Compute Optimizer reads have separate opt-ins. Missing or denied scope cannot become complete inventory or zero commitment exposure.
- Exact native responses and canonical snapshots use versioned immutable objects and readback hashes. ClickHouse retains complete metric payloads, dimensions, units, statistics, timestamps, periods and native sample counts. PostgreSQL retains bounded evaluation references under forced tenant RLS. Failed collection cannot publish a complete replacement snapshot.
- Directed cluster/member and replica/source relationships preserve reviewed graph history. Ownership and configuration authority remain customer evidence. Unowned databases and resource-less charges remain visible.
- IDs-only asynchronous requests freeze server-selected evidence and the safety-profile version. A separately credentialed `finops_database_analyst` processes a durable PostgreSQL queue and publishes immutable advice. It cannot sign plans, assume customer execution roles or mutate databases. Existing owned EC2 restoration retains its original authority.
- Screening evaluates CPU, allocated-minus-freeable memory, connections, storage, IOPS, throughput, network, latency, queue depth, replication, HA and independent application SLOs. It requires 14 complete non-production days, 30 production days or 90 seasonal days. Percentiles describe native period statistics, never raw query/event distributions. Incomplete native samples remain incomplete coverage.
- Native orderability and modification ranges do not establish sustained physical I/O capacity. The initial independent, documented non-burst baseline supports only **`db.r6i.8xlarge` and `db.r6i.12xlarge`**. The selected AWS documentation asset is separately versioned, hashed and archived; it is not labelled a native API observation. Usable IOPS and throughput are the lower of provisioned storage and the class baseline. Unknown and burst-dependent classes remain blocked. CPU, memory, processor and network capacity come from separate native catalogue evidence. Sources: [RDS hardware specifications](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/Concepts.DBInstanceClass.Summary.html), [EBS specifications](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ebs-optimized.html).
- Current class capacity is not projected backwards without exact full-hour CUR continuity, a matching native incarnation and creation before the evidence window. Class changes, recreation, missing hours and ambiguous covered usage block this inference. Pending modifications remain native structured evidence; an `available` status does not erase them.
- Economics uses customer native NET usage and compatible actual customer-rate witnesses. Continuing charges, credits and currencies remain distinct. Unknown commitment allocation, payer exposure, charge families or comparable rates block monetary advice. Public catalogue prices cannot fill a customer-rate gap. The retained 730-hour monthly comparison is a conditional screen, not a demand forecast or a verified saving.
- Coverage includes all detected AWS charges: analysed, observation-only, blocked and unsupported services, unowned resources and charges without resource identifiers. Positive billed charges form the denominator; credits and net totals are separate. Incomplete scope, unknown or zero denominators produce unavailable percentages. Only exact server-selected economic record IDs count as analysed; shared cluster charges cannot be counted twice.
- The normal authenticated console provides inventory, immutable assessment history, explanations, source references, candidate economics, blockers, recommendations and coverage. Optional provider advice retains the provider/our recommendation, difference and reason. Every proposal has R3 risk, `execution_authorized=false`, `executable=false`, `pre_execution_ready=false` and `verified_saving=null`.
